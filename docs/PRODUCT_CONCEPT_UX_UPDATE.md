# Meow World — Product Concept & UX Update

## Visual World, Home, Life Journey & Evaluation System

### 1. แนวคิดหลักของ Meow World

Meow World ไม่ควรถูกมองว่าเป็นเพียง Social App, Pet App หรือเกม และไม่จำเป็นต้องพึ่งพา VR เพื่อให้เกิดประสบการณ์แบบ Metaverse

แนวคิดหลักคือการสร้าง **Visual World ที่เชื่อมโยงกับชีวิตจริง**

> **Meow World ไม่ได้สร้างโลกดิจิทัลขึ้นมาแทนชีวิตจริง แต่สร้างพื้นที่ดิจิทัลที่ช่วยให้เรื่องราว ความสัมพันธ์ และความทรงจำจากชีวิตจริงมีตัวตนต่อไป**

ผู้ใช้สามารถเลือกวิธีใช้งานได้ตามความถนัด เช่น

* ใช้งานแบบปกติผ่านเมนูและ Form
* ใช้ Feed และ Community
* เข้าชม Home ของเพื่อน
* สำรวจ Town
* เดินเล่นในเมืองผ่าน GUI
* ในอนาคตสามารถรองรับ Immersive Interface เช่น VR ได้

ดังนั้น **VR เป็นเพียงหนึ่งใน Interface ไม่ใช่เงื่อนไขของ Meow World**

---

# 2. Visual World Principle

หลักการสำคัญของ UX คือ

> **"ให้ภาพมันเล่าเรื่อง"**

แทนที่จะให้ระบบใช้ข้อความอธิบายทุกอย่าง ผู้ใช้ควรสามารถเข้าใจสถานะ ความสัมพันธ์ กิจกรรม และคุณค่าบางส่วนจากสิ่งที่มองเห็นได้

ตัวอย่างเช่น Home ที่มี

* 🐱 สัตว์เลี้ยง
* 🧸 ของเล่น
* 🌸 การตกแต่ง
* 📸 Memories
* 🎉 Events
* 📖 Life Journey

สามารถทำให้ผู้เยี่ยมชมรับรู้ได้เองว่า Home นี้มีชีวิตและมีเรื่องราว โดยไม่จำเป็นต้องมีข้อความว่า

> "เจ้าของบ้านนี้รักสัตว์มาก"

หลักการนี้สามารถใช้กับ

* Home
* Farm
* Town
* Event
* Community
* Life Journey
* Reputation / Evaluation

ได้ทั้งหมด

---

# 3. Visual Language

GUI ควรสร้างภาษาภาพที่สม่ำเสมอ เพื่อให้ผู้ใช้เรียนรู้ความหมายจากโลกของ Meow World มากกว่าการเรียนรู้เมนูจำนวนมาก

ตัวอย่าง:

* 🏠 = Home
* 🐱 = Pet
* ❤️ = Relationship / Favorite / Affection
* 🎉 = Event
* 📚 = Knowledge / Meow Wiki
* 🛍️ = Marketplace
* 💬 = Community
* 📖 = Life Journey / Journal
* 🔒 = Private
* 🌱 = Growth / Development

แนวคิดคือ

> **Don't make users learn the interface. Let the interface become the world.**

ภาพควรเป็นตัวนำ และสามารถเปิดรายละเอียดเพิ่มเติมได้เมื่อผู้ใช้ต้องการ

ไม่ควรบังคับให้ Visual UI แทนข้อความทั้งหมด แต่ใช้แนวคิด **Progressive Information**

เช่น

```text
🏠
 ↓
แตะ
 ↓
🏠 Momo's Home
 ↓
แตะอีกครั้ง
 ↓
รายละเอียด
```

---

# 4. GUI สำหรับผู้ใช้หลายกลุ่ม

Meow World ควรรองรับผู้ใช้ที่มีความต้องการแตกต่างกัน โดยไม่บังคับทุกคนให้ใช้ Interface แบบเดียวกัน

### กลุ่มที่ไม่สนใจ Visual World

สามารถใช้สิ่งที่ตัวเองถนัด เช่น

* Form
* Search
* List
* Feed
* Standard UI

โดยไม่จำเป็นต้องเดินเล่นในเมือง

### กลุ่มวัยรุ่น / Gen Alpha

สามารถใช้ Visual World เป็น Interface หลัก

เช่น

```text
🏠    🎉    📚    🛍️
Home Event Wiki Shop
```

ผู้ใช้สามารถเข้าใจความหมายผ่านภาพและบริบท โดยไม่จำเป็นต้องอ่านเมนูจำนวนมาก

### หลักสำคัญ

**ระบบข้อมูลด้านหลังเป็นชุดเดียวกัน แต่ Interface สามารถแตกต่างกันได้**

---

# 5. Home เป็น "บ้านเลขที่" ของผู้ใช้

Home ไม่ใช่เพียงพื้นที่ตกแต่ง แต่เป็นจุดหนึ่งในโลกของ Meow World

แต่ละ Home สามารถมี **Home ID** เปรียบเสมือนบ้านเลขที่

ผู้ใช้สามารถค้นหา Home ของเพื่อนได้ผ่าน Home ID ตามสิทธิ์ที่เจ้าของกำหนด

เมื่อได้รับอนุญาต ผู้เยี่ยมชมสามารถเห็น

* การตกแต่ง
* สัตว์เลี้ยง
* Events
* Memories ที่เปิดเผย
* Life Journey บางส่วน
* กิจกรรมอื่น ๆ ที่เจ้าของอนุญาต

แนวคิดสำคัญคือ

> **การเห็นบ้านของผู้อื่นควรก่อให้เกิดแรงบันดาลใจโดยธรรมชาติ**

เช่น

> "อ๋อ บ้านตกแต่งแบบนี้ได้ด้วยเหรอ"

และอาจนำไปสู่ความต้องการสร้าง Home ของตัวเอง

ดังนั้น Home จึงทำหน้าที่ทั้งเป็น

* Personal Space
* Identity
* Social Space
* Discovery
* Inspiration

---

# 6. User ID และ Home ID

**User ID** และ **Home ID** ควรแยกหน้าที่กัน

### User ID

ใช้เป็นตัวตนระดับผู้ใช้ และสามารถเชื่อมโยงกับข้อมูลอื่น เช่น

* บทความ
* Community
* Marketplace
* Contribution
* Ownership
* Activity
* ความสัมพันธ์ระหว่างผู้ใช้

ดังนั้น User ID ยังคงมีประโยชน์ แม้ผู้ใช้ยังไม่มี Home

### Home ID

ใช้ระบุตัว Home โดยเฉพาะ

รองรับกรณีที่ผู้ใช้หนึ่งคนอาจมีมากกว่าหนึ่ง Home เช่น

* Primary Home
* Secondary Home
* Home อื่น ๆ ในอนาคต

การมีหลาย Home จึงไม่ควรผูกว่า

> 1 User = 1 Home

โดยตรง

---

# 7. Friend / Home Relationship

การ Add Friend ไม่จำเป็นต้องหมายความว่าเราต้องเห็นทุกอย่างของอีกฝ่าย

ควรแยกสิทธิ์ระหว่าง

* User relationship
* Home visibility
* Pet visibility
* Memory visibility
* Event participation
* Private information

เพื่อรองรับกรณีที่ผู้ใช้มีหลาย Home และบาง Home ต้องการความเป็นส่วนตัวมากกว่า Home หลัก

โดยเฉพาะ **Secondary Home** ควรมีระบบ Privacy ที่ชัดเจน

---

# 8. การค้นหาและเยี่ยมชม Home

เมื่อเมืองมีขนาดใหญ่ขึ้น ไม่ควรบังคับให้ผู้ใช้เดินหา Home ของเพื่อนด้วยตัวเอง

ควรมีหลายระดับของการสำรวจ

### Level 1 — Town Overview

เห็นภาพรวมของเมือง โดยให้น้ำหนักกับจุดสำคัญ

### Level 2 — Town Emotion

เห็นกิจกรรม ความหนาแน่น Events และสถานะของเมืองในรูปแบบ Visual

### Level 3 — Walk Mode

ผู้ใช้สามารถเดินเล่นในเมืองได้เหมือนการสำรวจพื้นที่แบบ Street View

อย่างไรก็ตาม Walk Mode เป็น **ประสบการณ์เสริม** ไม่ใช่ช่องทางเดียวในการค้นหา Home

การ Add Friend / Home และการเข้าถึงจาก Feed หรือ Event สามารถพาผู้ใช้ไปยัง Home ได้โดยตรง

---

# 9. Community และ Meow Wiki

Community ยังคงทำหน้าที่เป็นพื้นที่สนทนาและแลกเปลี่ยนประสบการณ์

เมื่อพบกระทู้หรือข้อมูลที่มีคุณค่าและเป็นประโยชน์ต่อผู้ใช้ในระยะยาว สามารถคัดเลือกและจัดเก็บเข้าสู่ **Meow Wiki**

ตัวอย่างหัวข้อ:

* ความรู้สำหรับผู้เริ่มต้นเลี้ยงสัตว์
* สิ่งที่ควรรู้ก่อนเลี้ยง
* สิ่งที่ควรระวัง
* อาหารที่ไม่ควรให้สัตว์กิน
* ความรู้เฉพาะสายพันธุ์
* ประสบการณ์ที่มีประโยชน์จาก Community

Community จึงเป็นพื้นที่ที่ความรู้เกิดขึ้น

ส่วน Meow Wiki เป็นพื้นที่ที่ความรู้ถูกจัดระเบียบและเก็บรักษาไว้

---

# 10. เครดิตเจ้าของข้อมูล / Hall of Fame

เมื่อข้อมูลหรือบทความจาก Community ถูกคัดเลือกเข้าสู่ Meow Wiki เจ้าของข้อมูลควรได้รับการให้เครดิต

อาจมี Notification เช่น

> "บทความของคุณได้รับการคัดเลือกเข้าสู่ Meow Wiki"

และสามารถมีระบบ Recognition เช่น

* Badge
* Contribution
* Hall of Fame
* Contributor Profile

หลักการสำคัญคือ **สร้างแรงจูงใจด้วยการให้คุณค่าและการยอมรับ ไม่ใช่การแข่งขัน**

---

# 11. บทความใหม่ที่ดีกว่าบทความเดิม

หากมีบทความใหม่ที่มีคุณภาพมากกว่า ไม่ควรลบบทความเดิมหรือทำให้เจ้าของเดิมรู้สึกว่าผลงานถูกลดคุณค่า

ให้มองเป็นความสัมพันธ์แบบ

> **ต้นแบบ → การต่อยอด**

ตัวอย่าง:

```text
Article A
ต้นแบบ / Original Contribution
        ↓
Article B
ต่อยอด / Improved Version
        ↓
Article C
Further Development
```

บทความใหม่ควรให้เครดิตย้อนกลับไปยังต้นทาง

ดังนั้นคุณค่าของ A ไม่ได้หายไป แต่กลายเป็นส่วนหนึ่งของประวัติศาสตร์ขององค์ความรู้นั้น

---

# 12. Life Journey

**Life Journey เป็นหนึ่งใน Core Concept ของ Meow World**

ข้อมูลที่เกิดขึ้นระหว่างชีวิตของสัตว์เลี้ยงสามารถกลายเป็น Timeline เช่น

```text
🐣 วันแรก
   ↓
🏠 วันแรกที่กลับบ้าน
   ↓
🧸 ของเล่นชิ้นแรก
   ↓
🏥 พบแพทย์
   ↓
💉 วัคซีน
   ↓
⚖️ น้ำหนัก
   ↓
🎉 Event
   ↓
❤️ Memories
```

Life Journey ไม่ควรเป็นเพียง Data Timeline แต่เป็น **Story of a Life**

---

# 13. Life Journey → AI Story / Short Video

ข้อมูลใน Life Journey สามารถนำมาใช้สร้าง Clip / Short Video ในโอกาสต่าง ๆ ได้

ตัวอย่าง:

* 🎂 Birthday
* 🏡 Adoption Anniversary
* 🎉 Event
* ❤️ Friendship
* 📖 Year in Review
* 🌱 Growth Journey
* 🌈 Memorial / Remembrance

ระบบควรทำหน้าที่คล้าย **Digital Editor** มากกว่าเป็นเพียง Video Generator

คือเลือก Moment ที่มีความหมาย จัดลำดับ และสร้างเรื่องราวจากข้อมูลจริง

```text
Life Data
   ↓
Memories
   ↓
Important Moments
   ↓
AI Story Selection
   ↓
Sequence / Rhythm
   ↓
🎬 Life Journey Video
```

หลักการสำคัญ:

> **เราไม่ได้สร้างเรื่องราวขึ้นมาใหม่ แต่ช่วยให้เจ้าของกลับไปพบเรื่องราวที่มีอยู่แล้ว**

---

# 14. Emotional Design ของ Life Journey

Life Journey ไม่ควรออกแบบให้เป็น "ระบบสร้างความเศร้า"

โดยเฉพาะเมื่อสัตว์เลี้ยงจากไป

เป้าหมายคือ **Flashback / Remembrance**

ไม่ใช่

> "ระบบกำลังบอกว่าคุณสูญเสียสัตว์เลี้ยง"

แต่เป็น

> "คุณกำลังย้อนกลับไปดูชีวิตที่เคยมีร่วมกัน"

ตัวอย่างแนวทาง:

> **"ขอบคุณสำหรับทุกวันที่เราได้อยู่ด้วยกัน"**

สิ่งสำคัญคือระบบไม่ควรบังคับอารมณ์ด้วยเพลงเศร้า คำพูด หรือ Visual ที่พยายามชี้นำมากเกินไป

ควรปล่อยให้ **ความทรงจำจริงเป็นผู้เล่าเรื่อง**

---

# 15. "ให้ภาพมันเล่าเรื่อง" กับ Life Journey

หลักการ Post-production:

> **"ให้ภาพมันเล่าเรื่อง"**

สามารถกลายเป็น Design Principle ของ Meow World

แทนที่จะบอกว่า

> "เจ้าของใส่ใจสัตว์เลี้ยงมาก"

ให้ Timeline และสิ่งที่เกิดขึ้นจริงเป็นตัวแสดงให้เห็น

```text
🏠 อยู่ด้วยกัน
↓
🍚 ดูแล
↓
💉 ดูแลสุขภาพ
↓
⚖️ ติดตามน้ำหนัก
↓
📸 เก็บความทรงจำ
↓
🎉 ใช้เวลาร่วมกัน
↓
❤️ มีประวัติชีวิตร่วมกัน
```

ผู้ใช้สามารถตีความคุณค่าจากเรื่องราวที่เห็นได้ด้วยตัวเอง

---

# 16. Farm และ Quality Signals

หลักการเดียวกันสามารถนำไปใช้กับ Farm

ไม่ควรแสดงเพียง

> ⭐ Farm Quality = 95/100

เพราะตัวเลขอาจทำให้ผู้ใช้รู้สึกว่ากำลังถูกตัดสิน หรือเกิดการพยายามปั่นคะแนน

ควรแสดงข้อมูลและประวัติที่สะท้อนการจัดการ เช่น

* Health Records
* Feeding Records
* Weight Records
* Veterinary Records
* Life Journey
* Events
* Activity History
* Community Contribution

จากนั้น Meow World สามารถนำข้อมูลเหล่านี้ไปใช้ในระบบ Evaluation ภายใน

---

# 17. Evaluation / Ranking Principle

แนวคิดสำคัญคือ

> **Evaluate Privately. Rank Publicly. Explain Contextually.**

ระบบสามารถมีคะแนนภายในเพื่อใช้ประเมินและจัดลำดับ แต่ **ไม่เปิดเผยคะแนนดิบให้ผู้ใช้เห็น**

ผู้ใช้เห็นเพียงผลลัพธ์ เช่น

```text
🥇 Farm A
🥈 Farm B
🥉 Farm C
```

โดยไม่จำเป็นต้องเห็น

```text
Farm A = 94.7
Farm B = 91.3
Farm C = 87.2
```

จุดประสงค์ไม่ใช่การสร้าง "คะแนนความดีของเจ้าของ"

แต่เป็นการประเมินคุณภาพของข้อมูล พฤติกรรม ประวัติ และบริบทที่เกี่ยวข้อง

---

# 18. Temporal Behavior

หนึ่งในองค์ประกอบสำคัญของ Evaluation คือ **เวลา**

ไม่ควรดูเพียงว่า

> "มีข้อมูลมากแค่ไหน?"

แต่ต้องดูว่า

> **"ข้อมูลเกิดขึ้นเมื่อใด และมีรูปแบบอย่างไรเมื่อวางลงบน Timeline?"**

ตัวอย่าง:

### Farm A

```text
ม.ค.  ⚖️ น้ำหนัก
ก.พ.  ⚖️ น้ำหนัก
มี.ค. 💉 วัคซีน
เม.ย. ⚖️ น้ำหนัก
พ.ค.  🏥 พบแพทย์
มิ.ย.  ⚖️ น้ำหนัก
```

ข้อมูลเกิดขึ้นต่อเนื่องและมี Temporal Pattern

### Farm B

```text
ม.ค.
ก.พ.
มี.ค.
เม.ย.
พ.ค.
มิ.ย.

30 มิ.ย.
████████████████
บันทึกข้อมูลย้อนหลังทั้งหมด
```

ไม่ควรสรุปทันทีว่า Farm B ไม่ใส่ใจ

เพราะอาจเป็นการนำข้อมูลจากระบบเดิม เช่น กระดาษหรือ Excel เข้ามาใน Meow World

ดังนั้นต้องแยก:

1. Historical Completeness
2. Recording Consistency
3. Temporal Accuracy
4. Expected Interval
5. Data Migration / Import Context

# 19. Expected Temporal Pattern

กิจกรรมแต่ละประเภทมีธรรมชาติของเวลาที่แตกต่างกัน

ตัวอย่าง:

```text
⚖️ น้ำหนัก
→ มีช่วงเวลาที่เหมาะสมในการติดตาม

💉 วัคซีน
→ ไม่ได้เกิดขึ้นทุกเดือน

🏥 พบแพทย์
→ เกิดตามความจำเป็น

🍚 Feeding
→ มีความถี่สูง

📖 Journal
→ ไม่จำเป็นต้องบันทึกทุกวัน
```

ดังนั้น Algorithm ไม่ควรกำหนดกฎเดียวกับข้อมูลทุกประเภท

ควรพิจารณาว่า

> **ข้อมูลประเภทนั้นควรเกิดขึ้นตามธรรมชาติอย่างไร**

---

# 20. Continuity vs Bulk Data

การบันทึกข้อมูลจำนวนมากในครั้งเดียวไม่ควรถูกลงโทษโดยอัตโนมัติ

สิ่งที่ระบบควรสนใจคือ **พฤติกรรมหลังจากข้อมูลเข้าสู่ระบบแล้ว**

เช่น

```text
Historical Data
██████████████
      ↓
Migration
      ↓
Live Recording
      ↓
วันนี้
      ↓
เดือนหน้า
      ↓
เดือนถัดไป
```

หากหลังจาก Migration แล้วมีการบันทึกอย่างต่อเนื่อง ระบบจึงสามารถเห็น Pattern ของการใช้งานจริงได้

---

# 21. Context Events

Timeline ต้องสามารถรองรับเหตุการณ์ที่อธิบายช่วงเวลาที่ไม่มี Activity ได้

เช่น

```text
Jan  Active
Feb  Active
Mar  Active
Apr  ⏸️ Temporary Closure
May  ⏸️ Temporary Closure
Jun  ▶️ Reopened
Jul  Active
```

ระบบไม่ควรตีความทุกช่วงเวลาที่ไม่มีข้อมูลว่าเป็น "การละเลย"

# 22. หลักการประเมินที่สำคัญ

Meow World ไม่ควรพยายามตอบว่า

> **"คนนี้เป็นคนดีหรือไม่?"**

แต่ควรตอบคำถามที่วัดได้มากกว่า เช่น

> **"รูปแบบข้อมูลและกิจกรรมมีความสม่ำเสมอ มีประวัติ และสอดคล้องกับบริบทมากน้อยเพียงใด?"**

ดังนั้น

> **จำนวนข้อมูล ≠ คุณภาพ**

และ

> **ความถี่ของข้อมูล ≠ ความใส่ใจ**

แต่

> **รูปแบบของข้อมูลเมื่อวางลงบนเวลา สามารถเป็นหนึ่งใน Quality Signals ได้**

---

# 23. Visual Reputation

Reputation ของผู้ใช้หรือ Farm ไม่จำเป็นต้องถูกนำเสนอเป็นตัวเลข

สามารถให้ผู้ใช้เห็นจากสิ่งที่เกิดขึ้นจริง

```text
📖 Long History
💉 Care Records
⚖️ Regular Tracking
🎉 Participation
❤️ Memories
🌱 Growth
🏆 Contributions
```

แนวคิดคือ

> **Don't score the person. Show their story.**

ระบบสามารถใช้ข้อมูลเหล่านี้ในการ Evaluation ภายในได้ แต่ไม่จำเป็นต้องนำคะแนนมาเป็นตัวตนของผู้ใช้

---

# 24. Metaverse / Visual World Philosophy

Meow World ไม่ควรนิยาม Metaverse ว่าเป็นโลกที่ผู้ใช้ต้องเข้าไปอยู่ตลอดเวลา

แต่เป็น:

> **โลกดิจิทัลที่ผู้ใช้สามารถกลับเข้าไปหาได้เมื่ออยากพบคน พบสัตว์เลี้ยง พบกิจกรรม หรือกลับไปหาความทรงจำ**

จึงไม่จำเป็นต้อง:

* ใส่ VR ตลอดวัน
* สร้าง Avatar ตลอดเวลา
* ทิ้งโลกจริงเพื่อเข้าโลกเสมือน

แต่เป็นการนำชีวิตจริงบางส่วนมาเชื่อมต่อกับโลกดิจิทัล

```text
REAL LIFE
    ↓
Photos / Memories / Events / Records
    ↓
🌎 MEOW WORLD
    ↓
Home / Town / Community / Life Journey
```

แนวคิดสามารถสรุปได้ว่า:

> **Tamagotchi 4.0 with Real Life**

แต่แตกต่างจาก Tamagotchi ตรงที่สัตว์เลี้ยงในโลกนี้ไม่ใช่สัตว์ดิจิทัลที่ถูกสร้างขึ้นมาแทนของจริง

แต่เป็น

> **ชีวิตจริงที่ถูกบันทึกและเล่าเรื่องต่อในโลกดิจิทัล**

# 25. Core Design Philosophy

หลักการทั้งหมดสามารถรวมเป็นชุดเดียวได้ดังนี้

### 1. Free First

คุณค่าหลักของ Meow World ต้องเข้าถึงได้โดยไม่สร้างกำแพงตั้งแต่เริ่มต้น

### 2. Value Before Revenue

สร้างคุณค่าให้ผู้ใช้ก่อน รายได้ควรเป็นผลพลอยได้จากคุณค่าที่เกิดขึ้น

### 3. Visual First

ให้ภาพและบริบทช่วยสื่อสารแทนข้อความเมื่อเหมาะสม

### 4. Let the World Tell the Story

> **"ให้ภาพมันเล่าเรื่อง"**

### 5. Data Should Tell the Story

ข้อมูลที่สะสมตามเวลาควรสะท้อนประวัติและพฤติกรรมจริง

### 6. Evaluate Privately

ระบบสามารถประเมินภายในโดยไม่เปิดเผยคะแนนดิบ

### 7. Rank Without Shaming

การจัดอันดับไม่ควรทำให้คนรู้สึกว่าตัวเอง "ด้อยกว่า" จากคะแนน

### 8. Preserve Credit

การต่อยอดไม่ควรลบคุณค่าของต้นฉบับ ทุก Contribution ควรมีที่มาที่ไป

### 9. Real Life First

Meow World เป็นส่วนต่อขยายของชีวิตจริง ไม่ใช่สิ่งที่ต้องมาแทนชีวิตจริง

### 10. Memories Have Value

ข้อมูลบางอย่างไม่ได้มีคุณค่าเพราะนำไปวิเคราะห์ได้ แต่มีคุณค่าเพราะวันหนึ่งเจ้าของอยากกลับมาดูมันอีกครั้ง

    ↓
