# 🏠 Home Mode & Home Building — Design Specification

**App:** MEOW WORLD
**Version:** Heart Edition
**Date:** 2026-09-28
**Status:** 📘 Concept Locked (ยังไม่แตะ UI/Code — รอกำหนด Home Building Scope ก่อน)

---

## ❤️ หัวใจของ Meow World

> **Meow World จะถูกสร้างขึ้นด้วยหัวใจ**
> ไม่ใช่เพียงเพื่อสร้างพื้นที่ให้น้องอยู่
> แต่เพื่อให้คนที่รักน้อง **ได้ร่วมกันสร้างบางสิ่งให้เขา ได้เห็นมันเปลี่ยนแปลง และเติบโตไปพร้อมกัน**

แกนความรู้สึกของทั้งระบบ:

```
        ❤️ คน
         │  ร่วมกันสร้าง
         ▼
       🏠 Home
         │  เติบโต
         ▼
       🐈 น้อง
         │  ใช้ชีวิตร่วมกัน
         ▼
    📖 Life Journey
         │
         └──────► ความทรงจำ ──► ❤️
```

ทุกอย่างใน Meow World เน้นไปที่ **ความสัมพันธ์ ความผูกพัน และความทรงจำ**
ข้อมูล (Identity / Record) เป็น **เครื่องมือช่วยรักษาเรื่องราว ไม่ใช่เป้าหมายสูงสุด**

---

## 🧭 หลักการ (Principles) — ล็อกไว้เป็นเข็มทิศ

1. **"เก็บข้อมูลเพื่อรักษาความทรงจำ ไม่ใช่เก็บข้อมูลเพียงเพื่อให้มีข้อมูล"**
2. **"เทคโนโลยีควรช่วยให้ความสัมพันธ์เติบโต ไม่ใช่เข้ามาแทนที่ความสัมพันธ์"**
3. **"สร้างบ้าน" ≠ "Create Home record"** — การสร้างบ้านไม่ใช่การกรอกฟอร์มจบในวันเดียว แต่คือการ **ร่วมกันสร้างพื้นที่ของเรา**
4. **"บ้านที่ยังสร้างไม่เสร็จ" คือ State ที่ถูกต้องของระบบ** — ไม่ใช่ Error, ไม่ใช่ Incomplete Record
5. **ไม่มี Deadline ในการสร้างบ้าน** — หนึ่งวัน สามวัน หนึ่งสัปดาห์ บ้านก็ยังเป็นบ้านของเราตั้งแต่วันแรก
6. **Home Mode ไม่ได้แสดงว่า "ระบบสร้างบ้านไปถึงไหนแล้ว"** แต่แสดงว่า **"พวกเราได้สร้างอะไรให้บ้านและให้น้องร่วมกันไปถึงไหนแล้ว"** — แบบแรกคือ Software Progress แบบหลังคือ Shared Experience
7. **"เราไม่ได้วางข้อมูลไว้ตามความสำคัญของมันเพียงอย่างเดียว แต่ตามเวลาที่ชีวิตต้องการมัน"** — ข้อมูลที่สำคัญ ไม่จำเป็นต้องเป็นข้อมูลที่เราเข้าถึงบ่อยที่สุด (ดู Information Weight & Access Model)
8. **"Structured Data เป็น Default เมื่อข้อมูลนั้นมี Meaning ที่ระบบรู้จัก — Free Text เก็บไว้สำหรับ Human Expression จริง ๆ"** (ดู Stable Key & Free Text Policy)

> ตัวกรองตัดสินใจ Feature: ถ้า Feature ไหนทำให้ระบบเก็บข้อมูลได้มากขึ้น แต่ไม่ได้ช่วยความสัมพันธ์ ความผูกพัน หรือความทรงจำ — ต้องถามก่อนว่า *"เราจำเป็นต้องสร้างมันจริงหรือ?"*

## 🚪 App Entry — ตรวจสถานะเมื่อเปิดแอป

```
เปิด Meow World
        │
        ▼
   ตรวจสถานะ (Home? Pet?)
        │
 ┌──────┼──────────────┐
 │      │              │
 ▼      ▼              ▼
ไม่มี   มี Home       มี Pet
Home   ไม่มี Pet      ไม่มี Home
 │      │              │
 ▼      ▼              ▼
Welcome  Home Mode     Home Mode
Entry    Empty         Empty
 │       + Invite      + Pet beside
 │       to build      the house
 │
 └──────────────┐
                ▼
        มีทั้ง Home + Pet
                │
                ▼
        Home Mode เต็มรูปแบบ
```

### กรณี 1 — ยังไม่มี Home และ Pet → **Welcome Entry**

Entry Point ของโลก (ไม่ใช่ Home Mode) ประกอบด้วย 3 ทางเลือก:
- 🏠 สร้างบ้าน
- 🐈 เพิ่มสัตว์เลี้ยง
- ⌁ Scan QR

ตาม spec เดิมที่ `docs/WELCOME_ENTRY_SCREEN_DESIGN_SPEC.md` (Living Mode, ภาพเล่าเรื่องเป็นพระเอก, บ้านเป็น Interactive Hotspot ไม่ใช่ปุ่ม)

### กรณี 2 — มี Home แต่ยังไม่มี Pet → **Home Mode (Empty + Invite to build)**

- เข้าสู่ Home Mode ได้แล้ว แต่บ้านยังไม่มีข้อมูล / ยังไม่เสร็จ
- กราฟฟิกเป็น **พื้นที่เปล่า** ที่ชวนคนในบ้าน "ร่วมกันสร้างบ้าน ใส่ข้อมูลบ้าน เพื่อรอรับน้องเข้าสู่บ้านของเรา"
- สารสำคัญ: บ้านไม่ได้ถูกสร้างเสร็จในครั้งเดียว

### กรณี 3 — มี Pet แต่ยังไม่มี Home → **Home Mode (Empty + Pet beside the house)**

- UX ที่ใส่ใจ: **Pet ไม่ได้ถูกทิ้งไว้นอกระบบ แต่กำลังรอให้บ้านของเขาเกิดขึ้น**

  ```
        🐈  น้องรออยู่
        🏠  บ้านกำลังสร้าง
  ```

- กราฟฟิกเป็นพื้นที่เปล่า ชวนผู้เลี้ยงร่วมสร้างบ้าน **โดยมีน้องนอนเล่นอยู่ข้าง ๆ บ้านที่กำลังสร้าง**

### กรณี 4 — มีทั้ง Home + Pet → **Home Mode เต็มรูปแบบ**

ลำดับความสำคัญ (Priority):

```
Home Mode
│
├── Life Journey        ← Primary (เน้นเขียนเรื่องราวเป็นหลัก)
├── Home Graphic        ← กดเพื่อดูข้อมูลทั้งหมดของบ้าน
└── Home Customization  ← ปรับแต่งบ้านได้ตลอดเวลา
```

Home Mode ไม่ใช่ Dashboard แบบธุรกิจ — มันคือ **Living Space**

## 🏗️ Home Building — บ้านที่ค่อย ๆ เติบโต

> **Home ไม่ใช่ Object ที่สร้างเสร็จด้วย Form เดียว แต่เป็นพื้นที่ที่ค่อย ๆ เติบโตจากการร่วมกันสร้าง**

ลำดับการเติบโตของบ้าน:

```
เริ่มสร้าง
   ↓
ค่อย ๆ เติมข้อมูล
   ↓
เห็นความคืบหน้า
   ↓
บ้านค่อย ๆ เป็นรูปเป็นร่าง
   ↓
พร้อมต้อนรับน้อง
```

- เวลาสร้างจริงโดยประมาณ: **~1 สัปดาห์** (ไม่เสร็จภายในวันเดียว)
- แต่ **ไม่มี Deadline** — ความเร็วไม่ใช่ตัวชี้วัด ความหมายต่างหากที่สำคัญ

### Home Building Progress — แสดงเป็น "บ้านของเรากำลังเติบโต" ไม่ใช่ "60% complete"

```
🏠 บ้านอุ่นไอรัก

กำลังสร้างบ้านของเรา
██████░░░░ 60%

สิ่งที่เราช่วยกันสร้างแล้ว
✓ ชื่อบ้าน
✓ สมาชิก
✓ น้อง ๆ
○ เรื่องราวของบ้าน
○ ความทรงจำแรก
○ ...
```

- **Progress คือส่วนหนึ่งของ Home Identity / Home Mode** ไม่ใช่แค่ Progress Bar ของฟอร์ม
- สิ่งที่แสดงคือ "สิ่งที่พวกเราช่วยกันสร้างแล้ว" ไม่ใช่ "ระบบทำงานไปถึงไหนแล้ว"

### ความรู้สึกเป้าหมายของ Home Building

> **เน้นความรู้สึกในความเป็นเจ้าของร่วมกัน — ได้สร้างสิ่งหนึ่งให้น้องด้วยกัน ได้เห็นการเปลี่ยนแปลงและเติบโตไปพร้อม ๆ กัน**

จังหวะของ Shared Experience:

- คนในบ้านทำอะไรบางอย่าง → บ้านเปลี่ยน
- กลับมาอีกวัน → เห็นสิ่งที่เปลี่ยน
- น้องเข้ามาอยู่ → บ้านมีชีวิต
- บันทึก Life Journey → เรื่องราวเพิ่มขึ้น

และเมื่อเวลาผ่านไป คนจะมองย้อนกลับมาได้ว่า: **"บ้านหลังนี้ เราสร้างมาด้วยกัน"**

## 🧱 โครงสร้าง Concept 3 ชั้น

```
Home Identity
     │  บ้านนี้คือใคร
     ▼
Home Building
     │  เรากำลังร่วมกันสร้างอะไร
     ▼
Home Mode
     │  บ้านที่เราใช้ชีวิตอยู่ด้วยกัน
     ▼
Life Journey
```

### บทบาทของแต่ละส่วน (ตัวเชื่อมกับแนวคิดเดิม)

| ส่วน | ตอบคำถาม | หมายเหตุ |
|------|-----------|----------|
| **Home Identity** | "เราอยู่ร่วมกันที่ไหน และเราเป็นใครในบ้านนี้" | ต่อยอดจาก "Home = บ้านเลขที่" ใน `PRODUCT_VISION.md` |
| **Pet Identity** | "น้องคือใคร" | ข้อมูล structured รับใช้เรื่องราว (เชื่อม `petIdentity` ที่ implement แล้ว) |
| **Home Building** | "เรากำลังร่วมกันสร้างอะไร" | State การเติบโตของบ้าน — เป็น State ถูกต้อง ไม่ใช่ record ค้าง |
| **Home Mode** | "เราใช้ชีวิตร่วมกันอย่างไร" | Living Space — กราฟฟิกด้านบน กดดูข้อมูล ปรับแต่งได้ตลอด |
| **Life Journey** | "เราเคยมีช่วงเวลาอะไรด้วยกันบ้าง" | Primary ของ Home Mode เต็มรูปแบบ |

### คุณค่าระยะยาว

สิ่งที่มีค่าที่สุดในระยะยาว ไม่ใช่ "น้องเป็นแมวสีอะไร" แต่คือ:

- "วันที่น้องเข้ามาในบ้านเป็นวันไหน"
- "ครั้งแรกที่น้องกล้านอนตรงนี้"
- "วันนี้น้องทำอะไรให้เราหัวเราะ"
- "เราเคยผ่านช่วงเวลานั้นมาด้วยกันอย่างไร"

> **Identity จึงควรรับใช้ Memory ไม่ใช่ให้ Memory เดินตามโครงสร้างข้อมูล**
> (สอดคล้องกับ Event-first storage ใน `docs/EVENT_STORAGE_DESIGN.md` และ Principle "Memories Have Value" ใน `docs/PRODUCT_VISION.md`)

## ⚖️ Information Weight & Access Model (2026-09-28 เพิ่มเติม)

> **เราไม่ได้กำลังบอกว่า Passport "ไม่สำคัญ"** — แต่เราแยก **ความสำคัญของข้อมูล** ออกจาก **ความถี่ในการเข้าถึงข้อมูล**

### 4 บทบาทของพื้นที่ใน Meow World

| พื้นที่ | บทบาท | น้ำหนัก |
|---------|--------|---------|
| **Welcome Entry** | เราสร้างบ้าน | ประตูเข้าสู่การสร้างความสัมพันธ์และบริบทของบ้าน — น้ำหนักที่การสร้างบ้าน + นำเข้าข้อมูลเบื้องต้นของน้อง (Home Identity / People / Pets / ความสัมพันธ์เบื้องต้น) |
| **Graphic UI** | เราเข้าถึงบ้านผ่านสิ่งที่มีความหมาย | Spatial / Relationship Interface — ความถี่สูง |
| **Home Mode** | เราใช้ชีวิตร่วมกันและสร้าง Life Journey | แกนหลักคือ Life Journey — ความถี่สูง |
| **Passport** | เราเก็บรายละเอียดไว้พร้อม เมื่อชีวิตต้องการมัน | Deep Information / Need-based Access — ความสำคัญสูง แต่ความถี่ต่ำ |

### Information Weight Table

| สิ่ง | ความถี่ในการเข้าถึง | บทบาท |
|------|---------------------|--------|
| Home / Graphic | สูง | ใช้ชีวิตกับบ้าน |
| Life Journey | สูง | บันทึกและย้อนความทรงจำ |
| Relationship | สูง | เข้าใจคนและน้อง |
| Memories | สูง | ความผูกพัน |
| Passport | ต่ำกว่า | ข้อมูลอ้างอิงเมื่อจำเป็น |
| Medical / Vet info | ตามเหตุการณ์ | ใช้เมื่อถึงเวลา |
| Identity details | ตามเหตุการณ์ | ใช้เมื่อต้องการตรวจสอบ |

### Graphic UI = Spatial / Relationship Interface

Graphic UI ไม่ใช่แค่ "ภาพสวย ๆ ของบ้าน" แต่เป็น **อีกหนึ่งเครื่องมือหลักในการเข้าถึงข้อมูล** — ผู้ใช้เข้าถึงสิ่งต่าง ๆ ผ่าน **ความสัมพันธ์** ที่มองเห็น:

```
                 🏠 HOME
                    │
        ┌───────────┼───────────┐
        │           │           │
       👤          👤          🐈
       คน          คน         น้อง
        │                       │
        └──────────┬────────────┘
                   │
              ❤️ Relationship
                   │
              📖 Life Journey
                   │
              🧠 Memories
```

เข้าถึงได้ผ่านกราฟฟิก: บ้าน / คน / น้อง / ความสัมพันธ์ระหว่างคนกับคน คนกับสัตว์เลี้ยง และสัตว์เลี้ยงกับสัตว์เลี้ยง / เรื่องราว / ความทรงจำ / และข้อมูลรายละเอียดเมื่อจำเป็น

> **ข้อมูลไม่ได้ถูกเข้าถึงด้วย Menu อย่างเดียว แต่เข้าถึงผ่าน "ความหมาย" ของสิ่งที่ผู้ใช้กำลังมองเห็น**
> (ต่อยอด Principle "Visual First / Let the World Tell the Story" ใน `PRODUCT_VISION.md`)

### Passport: จาก Primary Interface → Supporting Information Layer

Passport **ไม่หายไป** แต่ลดบทบาทลงอย่างมีเกียรติ:

- เดิม (มุมมองเก่า): Passport เป็นศูนย์กลางข้อมูลของน้องที่ต้องเปิดบ่อย
- ใหม่ (Access Model): Passport คือ **Deep Information Layer** — เปิดเมื่อชีวิตต้องการ เช่น พาน้องไปหาหมอ, ตรวจข้อมูล Identity, ดูประวัติการแพทย์/วัคซีน
- ธรรมชาติของ Passport ที่เป็น **Living Document ที่โตทีละขั้น** (`MEOW_PASSPORT_DESIGN_SPEC.md`) ยังคงเดิมทั้งหมด — เปลี่ยนเพียง **ตำแหน่งในการเข้าถึง** ไม่ใช่คุณค่าของข้อมูล

**ภาพรวม flow:**

```
              WELCOME ENTRY
                    │
          🏠 Build the Home
                    │
          ┌─────────┴─────────┐
          │                   │
      Home Identity       Pet Identity
          │                   │
          └─────────┬─────────┘
                    ↓
                HOME MODE
                    │
              📖 LIFE JOURNEY
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
   Relationship   Memories    Daily Life
       │
       ↓
   Graphic UI
       │
       ├── People
       ├── Pets
       ├── Home
       └── Relationships
                    │
                    ↓
              Passport
          (เมื่อถึงเวลาจำเป็น)
```

> **Passport ไม่ใช่ที่ที่เราใช้ชีวิต แต่เป็นที่ที่เราไปเมื่อจำเป็นต้องรู้ข้อมูล**
> ในชีวิตประจำวัน เราเปิด Home Mode เพื่ออยู่กับความทรงจำและความสัมพันธ์ของเรา

### ผลต่องานที่มีอยู่ (สำหรับอนาคต)

- Progressive Passport ที่ implement ไว้ (`ProgressivePassport.tsx`, โครงสร้างใน `RECONCILE_REPORT_PASSPORT_JOURNEY.md`) ยังใช้ได้ทั้งหมดในฐานะ **Supporting Information Layer** — ไม่ต้องรื้อ แต่จุดเข้าถึงใน UI จะถูกจัดตำแหน่งใหม่เมื่อทำ Home Mode จริง
- การจัดลำดับหน้าจอ: ผู้ใช้ควรเจอ Welcome Entry → Home Mode → Graphic UI ก่อน Passport เสมอ (Passport เข้าถึงผ่านน้อง/เหตุการณ์ ไม่ใช่เมนูหลัก)

## 🔑 Stable Key & Free Text Policy (2026-09-28 เพิ่มเติม)

> **อย่าให้ข้อมูลที่ระบบควรรู้ความหมาย กลายเป็นข้อความที่ระบบต้องเดาความหมายภายหลัง**

- **Stable Key = ความหมายของข้อมูล** (ระบบค้นหา / filter / aggregate / validate / translate / relate ได้)
- **Localized Label = วิธีที่มนุษย์มองเห็นข้อมูล** (en → Scottish Fold, th → สก็อตติชโฟลด์)

```
ความหมาย → Stable Key → Data Contract → Localized Label → UI
```

ตัวอย่างที่ implement แล้วใน repo: breed — `breed_key = "scottish_fold"` ไม่ใช่ free text 4 รูปแบบ (ดู `src/utils/petIdentity.ts` + CHECK-locked vocabulary)

**Free Text ยังมีที่อยู่** — ใช้เฉพาะข้อมูลที่ธรรมชาติเป็นข้อความอิสระจริง ๆ: ชื่อบ้าน, ชื่อเล่น, บันทึกความทรงจำ, เรื่องราว, Note จากเจ้าของ

> **ระบบดูแลความหมายของข้อมูล เพื่อให้มนุษย์มีอิสระในการบอกเล่าเรื่องราวของตัวเอง**

### Field Classification — Home Identity MVP

| Field | ประเภท | เหตุผล |
|-------|--------|--------|
| Home Name | Free Text | Human Expression — ชื่อบ้านคือการเล่าเรื่อง |
| Home Description | Free Text (optional) | Human Expression |
| Person Display Name | Free Text | Human Expression — ชื่อคนไม่ใช่ taxonomy |
| Home Membership | Structured (`home_members` FK) | ระบบต้องรู้ — ใครอยู่บ้านไหน |
| Role / Permission | Structured (`owner / editor / viewer`) | ระบบต้อง validate |
| Pet fields (species/breed/colors/pattern) | Structured แล้ว | ตาม `petIdentity.ts` + CHECK-locked vocab |
| relationship_key (เช่น คู่ชีวิต/ลูก) | ❌ **ยังไม่สร้าง** | ยังไม่ใช่ Requirement ของ MVP — สร้างเมื่อมี requirement จริง ตามหลัก "มีข้อมูลให้ แต่ไม่ตัดสิน" |

## ⏭️ Next Step (ก่อนแตะ UI/Code)

**กำหนด Home Building Scope:**

> "หนึ่งสัปดาห์นั้น เราต้องสร้างอะไรบ้าง จึงจะถือว่า Home พร้อมรับน้อง?"

สิ่งที่ต้องตัดสินใจใน scope:
1. Checklist ของ "สิ่งที่เราช่วยกันสร้างแล้ว" มีอะไรบ้าง (ชื่อบ้าน / สมาชิก / น้อง / เรื่องราวของบ้าน / ความทรงจำแรก / ...)
2. อะไรคือเงื่อนไข "พร้อมต้อนรับน้อง" (Minimum Home)
3. Data model: สถานะการเติบโตของบ้านเก็บเป็น Event อย่างไรให้เข้ากับ `EVENT_STORAGE_DESIGN.md`
4. Graphic states: พื้นที่เปล่า → ร่างแรก → ค่อย ๆ สมบูรณ์ แสดงความคืบหน้าบนกราฟฟิกอย่างไร
5. Access Paths (จาก Information Weight & Access Model): กำหนดจุดเข้าถึงของแต่ละชั้นข้อมูล — Graphic UI เป็นทางเข้าหลักเชิงความสัมพันธ์, Passport เข้าถึงแบบ need-based (เช่น จากหน้าน้อง / เหตุการณ์พาไปหาหมอ) และยืนยันว่าไม่มีชั้นข้อมูลใดถูกทิ้ง
6. ⚠️ **Known Limitation (ตั้งใจค้างไว้ — ห้ามมองว่าเป็น bug):** `/pets`, `/pets/birth`, `/pets/litters`, `/pets/[id]`, `/nests` ใช้ `homes[0].id` (บ้านแรกของ owner) เสมอ — **Multi-home ถูกต้องใน Domain/Schema แล้ว แต่ Active/Current Home selection ยังไม่ถูก implement** เป็น Future Gate ตามโจทย์ "User 1 คนมีได้หลาย Home + Active/Current Home ภายหลัง" — ห้ามขยาย Scope ไปทำในรอบ Home Identity MVP
